# Memory Hub 使用文档（给新用户）

## 这是什么

Memory Hub 是一个 macOS 后台小工具，把你本机多个 AI 编程助手
（Claude Code / Codex / Qoder / QoderWork / 悟空）各自积累的「记忆文件」
自动汇总到一处，用 LLM 去重、归并成主题 wiki，再安全地写回各家 ——
效果是：**你在 A 工具里沉淀的经验，B 工具也能直接用上，全程无需手动搬运**。

安全底线：

- 对各 App 的记忆目录**只读摄取**，写回前自动备份，写坏可一键回滚；
- API Key 只存 macOS Keychain，绝不落盘、绝不打印；
- 写入 wiki 前自动脱敏（sk- 开头密钥等一律打码）。

## 运行要求

- macOS（依赖 Keychain / launchd / FSEvents，不支持 Windows / Linux）
- Node.js ≥ 24（`node --version` 检查）
- 一个 OpenAI 兼容的 LLM API Key（整理归并需要；没有也能跑，只是不做 LLM 整理）

## 安装（约 2 分钟）

```bash
cd memory-hub        # 解压/克隆后的代码目录
npm install
npm link             # 注册全局命令 hub（nvm 环境无需 sudo）
hub --version        # 验证
```

## 首次配置（四步）

### 1. 初始化 + 自动探测

```bash
hub init
```

自动创建目录、生成默认配置，并扫描本机装了哪些 AI App 及其记忆位置。
没装的 App 会自动禁用，不影响其他。

### 2. 配置 LLM Key（三选一）

**方式 A —— 本机已有可同步的密钥来源**（Codex 登录态 / shell 里 export 过
`IDEALAB_API_KEY` 或 `ANTHROPIC_API_KEY`）：

```bash
hub keys --sync      # 只读同步进 Keychain
hub keys             # 查看有哪些条目（脱敏显示）
```

**方式 B —— 先把 Key 写进 shell 配置再同步**（例：内网 idealab）：

```bash
echo 'export IDEALAB_API_KEY=你的Key' >> ~/.zshrc
hub keys --sync
```

**方式 C —— 手动写入 Keychain**（任意 OpenAI 兼容服务都行）：

```bash
security add-generic-password -U -s memory-hub -a mykey -w '你的APIKey'
```

然后选定要用的条目，并补齐端点与模型（示例为 idealab + qwen3-max，按需替换）：

```bash
hub keys use idealab \
  --base-url https://idealab.alibaba-inc.com/api/openai/v1 \
  --model qwen3-max
```

### 3. 安装后台守护

```bash
hub daemon install   # 开机自启 + 崩溃自动拉起
```

### 4. 确认状态

```bash
hub status           # 一屏汇总：App 发现情况 / daemon 是否在跑 / 最近动作
```

## 日常使用：什么都不用做

装好之后全自动运行：

- 后台实时监听各 App 记忆文件的变化，增量摄取；
- 短时间内变更积累到阈值（缺省 5 条或 64KB）→ 静默合并约 2 分钟 → 自动
  LLM 整理并立即写回各 App；
- 零星小变更由每小时一次的兜底扫描收口；
- 电脑重启 / daemon 停过机也不用管，启动后 30 秒自动补齐欠账。

想看结果就打开 **`~/Desktop/Memory Hub/`**：

| 目录 | 内容 |
| --- | --- |
| `wiki/` | 整理后的主题记忆页（人可直接读） |
| `sources/` | 各 App 的原始快照（只增不改，留档） |
| `_index/master-index.md` | 全部 wiki 页的目录索引 |
| `logs/` | 运行日志镜像（误删无碍） |

## 常用命令速查

| 命令 | 什么时候用 |
| --- | --- |
| `hub status` | 想知道它有没有在干活 |
| `hub sync` | 手动跑一次完整链路（摄取→整理→写回），排障用 |
| `hub backup` | 大改动前手动做一份全量备份 |
| `hub rollback` | 写回结果不满意，恢复到备份（有二次确认） |
| `hub daemon stop` / `start` | 临时停用 / 恢复后台守护 |
| `hub daemon uninstall` | 彻底卸载后台守护（可逆，重装即恢复） |
| `hub config` | 查看当前配置（`~/.memory-hub/config.json`） |

## 常见问题

**Q：`hub status` 显示 daemon 未运行？**
`hub daemon start` 拉起；反复失败看 `~/.memory-hub/logs/launchd.err.log`。

**Q：日志里有 "distill 降级跳过 / llm 未配置"？**
LLM Key 没配好，回到「首次配置第 2 步」；期间快照会保留，配好后自动补整理。

**Q：某个 App 我不想被写回？**
编辑 `~/.memory-hub/config.json`，给对应 `apps[]` 条目加 `"readOnly": true`
（只摄取不写回）。悟空这类有云端同步的 App 建议开启。

**Q：写回把记忆文件写坏了？**
`hub rollback` 恢复最近一次备份；每批写回前都自动备份，不会丢。

**Q：觉得整理太频繁 / 太慢？**
调 `config.json` 的 `daemon` 块：`triggerCount`（条数阈值）、`quietMs`
（静默合并窗口）、`sweepIntervalMs`（兜底扫描间隔）。

## 卸载

```bash
hub daemon uninstall           # 摘除 launchd 守护
npm unlink -g memory-hub       # 移除全局命令（在代码目录里执行 npm unlink 亦可）
rm -rf ~/.memory-hub           # 删内部数据（可选）
# ~/Desktop/Memory Hub/ 是你的记忆资产，按需自行处理
```
